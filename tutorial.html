0开始之前

先花 5 分钟弄懂三个问题，后面的路会顺很多

0.1 这个项目做了什么？一句话

把 22,001 个模拟的「兴趣点」画在一张中国地图上，让它们可以按省份、按分类筛选查看。

什么是 POI？ POI = Point of Interest（兴趣点）。地图上任何一个有名字的地点——一家餐厅、一所学校、一个地铁站——就是一个 POI。每个 POI 最核心的信息就是 3 样：叫什么、在哪（经纬度）、属于哪类。

本项目的数据是模拟生成的：坐标和名称是合成的，但「每个省多少点、每类多少点」的比例，来自 2013–2023 年全国 POI 数据湖的真实分布。所以它是一张「按真实比例尺缩小的中国 POI 全景图」，适合用来学习和验证可视化方案。

0.2 用了哪些技术？5 个名词一次搞懂名词表

1分析结果

下面两张图不是贴图，是本页用页面里的代码现场算出来的——顺便教你怎么「做分析」

1.1 数据总览

22,001模拟 POI 总数（<1MB）
34省级区域全覆盖
17标准分类（模拟覆盖 16 个）
76.7°E~135°E经度范围（纬度 18.4°N~54°N）
数据怎么读？每条 POI 就是 5 个字段的数组：[省份索引, 名称, 分类索引, 经度, 纬度]。例如 [0, "广告公司18", 4, 121.65, 31.25] 表示：上海（索引 0）的一家公司企业（索引 4），位于东经 121.65°、北纬 31.25°。索引对应的名称存在 meta 里——这种「索引 + 对照表」写法是为了把文件压到 1MB 以内。

省份 POI 数量 TOP 10
统计方式：遍历 22,001 条记录，按省份索引累加计数（代码见下方）

  1. 广东第一：2,120 个点（9.6%），接近全国的十分之一。
  2. TOP 6 合计约 42.7%：广东、江苏、山东、浙江、河南、四川——约六分之一的省份占了四成多的点。
  3. 东南密、西北疏：点位集中在前者，这是真实中国 POI 的分布规律（即「胡焕庸线」效应），模拟数据忠实还原了这一点。

这张图是怎么算出来的？统计逻辑只有几行——「分组计数」是数据分析最基础的动作，Excel 的数据透视表、SQL 的 GROUP BY、代码里的累加，本质都是它：

const provCount = {};              // 1. 准备一个空容器 {省名: 数量}
d.points.forEach(p => {
  provCount[p[0]] = (provCount[p[0]] || 0) + 1;  // 2. 见一个加一个
});

  2. 典型的长尾分布：头部少数类别占大头，尾部一堆小类别——金融 1.0%、住宿 0.9%、风景名胜 0.6%。「事件活动」类在本次模拟中未生成点位。这是 POI 数据的经典结构（近似幂律分布）。

1.4 一句话总结分析结果这是一张按真实分布比例生成的「缩小版」中国 POI 全景图：数量上广东领跑、东南沿海密集；结构上基础民生类占近半、专业类呈长尾。它验证了「模拟数据 + 轻量前端」足以承载真实数据的可视化原型——后续接真实数据时，只需替换 JSON 文件，页面代码一行不用改。

2.3 先跑起来：20 行核心代码最小可用版

别一上来就研究 120 行的完整版。先用下面的最小可用版跑通「数据 → 地图」，它只有 20 来行。在文件夹里新建 mini.html，粘贴保存：

mini.html — 最小可用版（可完整复制）
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>我的第一张 POI 地图</title>
  <!-- 第 1 步：引入 ECharts 库（从公共 CDN 加载，本地无需安装任何东西）-->
  <script src="https://cdn.jsdelivr.net/npm/echarts@5/dist/echarts.min.js"></script>
  <style>html,body,#map{height:100%;margin:0}</style>
</head>
<body>
  <!-- 第 2 步：放一个容器 div，地图将画在它里面 -->
  <div id="map"></div>
  <script>
  // 第 3 步：同时加载两份数据（点的数据 + 省界数据）
  Promise.all([
    fetch('poi_sim.json').then(r => r.json()),
    fetch('china_mainland.json').then(r => r.json())
  ]).then(([poi, china]) => {
    // 第 4 步：把下载好的省界"注册"为一张名叫 china 的地图
    echarts.registerMap('china', china);
    // 第 5 步：在容器里初始化图表
    const chart = echarts.init(document.getElementById('map'));
    // 第 6 步：把每个点转成 [经度, 纬度]（p[3] 是经度，p[4] 是纬度）
    const points = poi.points.map(p => [p[3], p[4]]);
    // 第 7 步：一张地图 + 一层散点，画！
    chart.setOption({
      geo: { map: 'china', roam: true },       // roam:true 允许缩放拖动
      series: [{
        type: 'scatter',                    // 散点图
        coordinateSystem: 'geo',              // 用经纬度定位
        data: points,
        symbolSize: 4,
        itemStyle: { color: '#58a6ff', opacity: .7 }
      }]
    });
  });
  </script>
</body>
</html>
⚠ 保存时的两个常见坑① 编码必须是 UTF-8（VS Code 右下角可见，默认就是）；② 文件名后缀是 .html 不是 .html.txt（Windows 需在「查看」中勾选「文件扩展名」确认）。另外它必须和两个 json 文件放在同一个文件夹。

2.4 逐行讲解：这 20 行在干什么

代码人话解释
<script src="…echarts.min.js">从 CDN（公共文件服务器）借来画图工具。等价于「装了 ECharts」，但本地什么都不用装
<div id="map">网页上的一个空盒子，指定 id，后面用名字找到它
fetch('poi_sim.json')让浏览器「去隔壁拿文件」。fetch 返回的不是数据本身，是一个「正在路上的包裹」
.then(r => r.json())包裹到了再拆——把文本解析成 JS 能用的对象。这是异步编程的最常见写法
Promise.all([...])两份文件同时去拿，都到齐了再进 .then()，比排队拿快一倍
echarts.registerMap('china', …)给省界数据起名叫 'china' 并登记入库，之后随时能用这个名字调取
echarts.init(el)在 div 里铺画布，之后所有图都画在这块画布上
poi.points.map(p => [p[3], p[4]])把 22,001 条记录各取第 4、5 列（索引 3、4），组装成 22,001 个 [经度,纬度]
chart.setOption({...})ECharts 是声明式的：你只管「描述」图长什么样（地图 + 散点 + 颜色），怎么画它负责。想改图？改完描述再 setOption 一次即可
✅ 检查点：看到什么算成功？一张深色中国地图轮廓，上面铺满蓝色小点，滚轮可缩放、拖拽可平移。这就是全部核心原理了——完整版的筛选、统计只是在这 20 行外面「加壳」。

2.5 在本地跑起来关键一步

⚠ 为什么不能直接双击 mini.html？双击 = file:// 协议。出于安全策略，浏览器在 file:// 下禁止 fetch 本地文件，控制台（按 F12 打开）会报 CORS 错误，页面地图空白。必须通过 http:// 访问——需要一个「本地小服务器」。下面三种任选其一：
A
VS Code + Live Server 插件（零基础最推荐）
  1. VS Code 左侧扩展图标（四个方块）→ 搜索 Live Server → 安装（发布者 Ritwick Dey，下载量最大那个）
  2. VS Code 打开你的文件夹（文件 → 打开文件夹）
  3. 右键 mini.html → Open with Live Server
  4. 浏览器自动打开 http://127.0.0.1:5500/mini.html，地图出现 ✅

加分项：保存代码时页面自动刷新，改一行看一眼，学习体验极佳。

B
Python 自带的超迷你服务器
终端（Mac: 终端 / Win: PowerShell），cd 进文件夹后执行
# Mac / Linux（系统自带 python3）
python3 -m http.server 8000

# Windows（装过 Python 的话）
py -m http.server 8000

然后浏览器访问 http://localhost:8000/mini.html。关闭终端即关闭服务。

C
装了 Node.js 的话
任意终端
npx serve .          # 会给出一个可访问的地址，浏览器打开即可

2.7 完整版 index.html 比 mini 版多了什么？

功能实现思路
筛选器（分类/省份下拉 + 密度滑块）原生 <select>/<input>，切换时触发 render() 重新过滤数据并 setOption——「改条件 → 重画」，声明式库的好处在此
密度滑块抽样降密：count % step !== 0 则跳过，点太多时只画 1/N，2 万点也流畅
统计卡片筛选后同步更新「当前展示点」数字，就是分组计数的活学活用
悬浮详情tooltip 的 formatter 回调：鼠标停在哪，就拼一段「名称 · 分类 · 省份」的 HTML 显示
简称转全称数据里存「广东」，地图边界里叫「广东省」——用 PROV_FULL 对照表翻译

2.8 动手练习（附答案）

在 mini.html 上改，每题 2~5 分钟。改完保存刷新即可见效，改坏了重头复制粘贴就是——这就是本地学习的最大优势。

练习 1 · 把点改成红色、变大一点

改 series 里的两个属性：

第 7 步中的两行
symbolSize: 6,
itemStyle: { color: '#ff6a3d', opacity: .7 }

体会：颜色是十六进制 RGB（红绿蓝各两位），#ff6a3d 就是橙红。去任何「颜色选择器」网页挑一个喜欢的色值贴进来。

练习 2 · 只显示「餐饮」类的点

在 map 那里加一行过滤（餐饮的分类索引是 0，见 meta.cats）：

第 6 步改为
const points = poi.points
  .filter(p => p[2] === 0)      // 只留分类索引为 0 的记录（餐饮）
  .map(p => [p[3], p[4]]);

体会：filter 负责「留谁去谁」，map 负责「转成经纬度」。像流水线一样串起来——这就是完整版筛选器的雏形。

练习 3 · 鼠标悬浮显示「名称 · 分类」

给 series 的每条数据带上名字，再配置 tooltip：

第 6、7 步改为
const points = poi.points.map(p => ({
  name: p[1], value: [p[3], p[4], p[1] + ' · ' + poi.meta.cats[p[2]]]
}));
chart.setOption({
  geo: { map: 'china', roam: true },
  tooltip: { formatter: p => '<b>' + p.data.name + '</b><br>' + p.data.value[2] },
  series: [{ type: 'scatter', coordinateSystem: 'geo', data: points, symbolSize: 4 }]
});

体会：散点悬停能显示信息了。完整版只是多拼了省份名，并把这些做成可复用的 render() 函数。

3常见问题

踩坑了先看这里，90% 的问题都在下面
打开网页，地图是空白的？
最常见原因：你是双击直接打开的（地址栏是 file:// 开头）。file:// 下浏览器禁止 fetch 本地文件，数据加载失败。按 2.5 节 用 Live Server 或 python3 -m http.server 走 http:// 访问即可。判断方法：按 F12 打开控制台，看到红色 CORS / fetch 报错就是这个问题。
控制台报「echarts is not defined」？
ECharts 的 CDN 没加载成功（断网、或网络访问 jsdelivr 慢）。刷新重试；仍不行就把 echarts.min.js 下载到文件夹里，引用改成 <script src="echarts.min.js">。
数据是真实的吗？
不是。坐标与名称是合成的模拟数据，但「每省多少点、每类多少点」的比例基于 2013–2023 全国 POI 数据湖的真实分布生成。用途是可视化原型验证——先跑通方案，再换真数据。
想换成真实数据怎么办？
保持同样的 JSON 结构生成 poi_sim.json 替换文件即可，页面代码一行不用改：两个字段必须保留（经纬度），索引对照表按你的分类/省份重做。数据量大时建议继续用「索引 + 对照表」压缩体积。
页面能扛多少个点？
ECharts 散点在几万到几十万级别都没问题（本页 2.2 万点很轻松）。再往上可：① 用密度滑块同款思路降采样；② 换 ECharts GL 的 3D 散点；③ 服务端先做聚合（热力图/蜂窝图）。
为什么要用索引存省份/分类，不直接存名字？
省体积。22,001 条记录里存一个数字 0 比存字符串「上海」省几十倍空间，文件从几 MB 压到 1MB 以内，浏览器加载快。对照表放 meta 里只存一份。这是数据工程里的常见手法（类似数据库的外键）。
GitHub Pages 国内访问慢/打不开？
